Processes

The three parts started by ./run_all.sh. "Restart pending" means a code or .env file was edited after the process started — it is still running the old version until you restart.

Data freshness

How recently each engine produced data. A full bar means it's overdue.

📜

Logs

Last activity and any error-looking lines near the end of each log (checked over the last ~64 KB). A quiet log for a live process can be normal between scans.

📡

Pipeline

LINE quota, the public site link, and state backups — these fail silently (a message never arrives, a backup silently stops) rather than crashing a process, so they're checked here explicitly.

🧰

Fix-it commands

Run these yourself in Terminal, from the project folder. This page only watches — it never restarts anything.

./run_all.sh bgrestart everything detached (safe: stops old copies first, runs tests)
./run_all.sh statusquick check of what's running
./run_all.sh stopstop web + bot + scanner
tail -50 app/logs/bot.logread the live engine's recent log
Templates (the page layouts) reload on their own — only .py and .env edits need a restart. The Cloudflare tunnel is separate: restarting the stack keeps the same public URL, but restarting the tunnel changes it.
